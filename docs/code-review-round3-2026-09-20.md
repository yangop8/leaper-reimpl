## 唯一剩余项：P2，空预测范围绕过 SST 预算检查

**位置：** [adapters/rocksdb/leaper_rocksdb.cc:253](../adapters/rocksdb/leaper_rocksdb.cc:253)，重点是 256–265 行。

当前逻辑大致为：

```cpp
for (const auto& range : ranges) {
  for (it->Seek(start); it->Valid() && it->key() < limit; it->Next()) {
    if (blocks_so_far() >= budget) { exhausted = true; break; }
  }
  if (exhausted) break;
}
```

`Seek(start)` 本身会读入数据块。若该预测范围在当前输出 SST 中没有键，Seek 会落到范围结束之后的下一个键，或使迭代器无效，于是完全不进入循环体。预算检查也随之跳过，继续对下一个范围 Seek。连续多个这样的范围，可以读遍文件而始终不触发停止。

这是范围到 SST 映射中的正常情况：预测候选覆盖全库，但预取逐个处理某次任务的输出 SST，某个全局热范围不一定出现在当前文件中。不需要修改训练模型或传入非法配置才能触发。

### 真实 SST 复现

- 无压缩，4 KiB 数据块，12,000 条记录，每值 100 字节，底层缓存 64 MiB。
- `range_size=1000`，第 i 个键为 `(2*i+1)*1000`，按正常的 16 位十进制格式编码。因此该 SST 只有奇数 ID 的范围有键。
- 用固定 oracle 选择偶数 ID 范围 `0,2,...,23998`，使测试不依赖模型训练；这些预测范围在当前文件中没有键。
- 适配器预取额度设为 32 块。通过公开的 flush Begin/Completed 回调触发 `warm_mode=sst`。

当前源码编译后运行，两次独立验证均得到：

```text
mode=sst gaps=1 range=1000 keys; budget=32 blocks;
actual counted=355 blocks, files=1, failed=0
```

`actual counted` 是适配器现有暖块计数口径，说明检查仍没有限制这条读取路径。对照组有范围内记录时，同一预算正常停在 32。

### 最小修复方向与验收条件

1. 保留现在的内层逐键预算检查。
2. 在每个范围开始 Seek 前检查剩余额度。
3. Seek 完成后，不论迭代器是否有效、键是否位于范围内，都检查本次 I/O 后的预算；耗尽就退出任务预取。
4. 加入“预测范围在本 SST 中为空”的回归用例；允许一个不可分割读取操作带来的明确有限超额，但不能继续扫描后续范围。

iterator 路径的额度会在一次 Prefetch 返回后扣减，本轮这个空范围漏洞定位于 SST 路径，不应据此把两种路径全部判为失败。
